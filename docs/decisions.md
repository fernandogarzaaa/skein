# Decisions

One-line rationale per ambiguity resolved during the build.

- 2026-09-09 — `graph.json` is the only derived file and is rewritten only by `rebuild_graph()`; humans/agents never hand-edit it.
- 2026-09-09 — Out-of-order concurrent appends resolve by last-write-wins on event `timestamp` (file order breaks ties).
- 2026-09-09 — Extra event type `node_removed` added (spec's minimum list had no delete); delete of a claimed node becomes `human_interrupt` instead.
- 2026-09-09 — Blast-radius overlap is a heuristic (`fnmatch` both directions + static-prefix check), not a sound glob-intersection proof; conservative misses are acceptable for v0.1.
- 2026-09-09 — `human_interrupt` with action edit/reassign parks a claimed node as `needs_human` and clears the claim; the supervisor aborts instead of completing.
- 2026-09-09 — Supervisor watch window starts at `run_node` entry so interrupts during claim/worktree setup are not missed (found via a failing test).
- 2026-09-09 — Multi-line `intent.completion` runs line-by-line with `shell=True` in the worktree; every command must exit 0 or the node goes to `failed`.
- 2026-09-09 — Adapter output tail (last line, 2000 chars) seeds the completion `handoff_note`; dependents read handoffs, not transcripts, which bounds (not eliminates) context growth.
- 2026-09-09 — `skein run` accepts only `--backend claude_code` in v0.1 and rejects anything else explicitly.
- 2026-09-09 — `status`/`claim`/`run` opportunistically run the reaper first so expired leases never silently block claims.
- 2026-09-09 — CLI graph/status views use ASCII glyphs only; Unicode block elements crash on Windows cp1252 consoles (found in live walkthrough).
- 2026-09-09 — `release` refuses terminal nodes (`done`/`failed`/`unclaimed`); releasing is for active leases, history is append-only.
- 2026-09-09 (real-CLI pass, claude 2.1.248) — adapter invokes `claude -p <prompt> --dangerously-skip-permissions --output-format text`: stub missed that headless file work needs the permission-skip flag and that output format must be pinned for the stdout contract.
- 2026-09-09 (real-CLI pass) — supervisor gained `adapter_timeout` (default 1800s, `--adapter-timeout` in CLI): a stalled agent process becomes `failed` evidence instead of hanging the poll loop forever; the stub's instant return hid the missing ceiling.
- 2026-09-09 (real-CLI pass) — TTL/heartbeat defaults unchanged: heartbeats renew continuously during the run so the 30-min TTL only bounds dead-agent detection, not run length; measured fast-fail latency ~7-11s, multi-minute success runs fit comfortably.
- 2026-09-09 (real-CLI pass) — real failure modes observed: org-disabled 403 (`exit=1`, message on stdout) and unrecognized-model error both record as `failed` with adapter + completion evidence, no hang/crash. Sandboxed paths (Temp dirs) fail with `FileSystem.access` before any API call — repos/worktrees must live in normal locations.
- 2026-09-09 (real-CLI pass) — successful agent edit NOT proven: this machine's login is org-blocked for Claude Code; needs ANTHROPIC_API_KEY or admin enable. README says exactly this; CI stays on the stub adapter.
- 2026-09-09 (real-CLI pass, part 2: success proven) — user supplied an OpenRouter key; claude has no OpenRouter auth path, so proof ran the REAL claude binary against a throwaway localhost proxy (stdlib-only, Temp dir, never committed) translating Anthropic Messages API to OpenRouter chat completions, driving a real free model (cohere/north-mini-code:free). Full `skein run` success path observed: claim → worktree → real file edit → verify → done with handoff + evidence (23-29s runs, live heartbeats).
- 2026-09-09 (real-CLI pass, part 2) — proxy fixes the CLI required: strip `?beta=true` from `/v1/messages` path matching, echo the REQUESTED model id back in responses (else "issue with the selected model"), synthesize SSE from a non-streamed completion. None of this touches skein: it is harness-only.
- 2026-09-09 (real-CLI pass, part 2) — free-model flakiness is real and the gate earns its keep: twice the model claimed "file created" (adapter exit 0) without writing; verification correctly marked `failed` both times. A retry then succeeded. No product change; recorded as evidence the gate works.
- 2026-09-09 (real-CLI pass, part 2) — `git_commit_log` now commits scoped to `.skein` (`git commit -- .skein`): live walkthrough showed user-staged files riding a log commit. Git's own `.git`-ignore plus worktree separation already keep worktree metadata out; no further change.
- 2026-09-09 (real-CLI pass, part 2) — OpenRouter key used in-memory only (env vars in the invoking shell, never written to disk; verified absent via search). Key was pasted in chat: recommend rotation.
- 2026-09-09 (Stage 8a) — one shared intent-to-prompt text in the engine; the profile schema carries no prompt template by design (spec's minimum schema), per-backend prompt tuning deferred until a real binary demands it.
- 2026-09-09 (Stage 8a) — Stage 8 sketch showed claude as `-p --permission-mode acceptEdits`, but the real-backend pass validated `-p --dangerously-skip-permissions --output-format text`; kept the validated flags since zero-observed-behavior-change outranks the sketch.
- 2026-09-09 (Stage 8b) — codex profile keeps spec-literal `exec --full-auto` although upstream now prefers `--sandbox workspace-write` (--full-auto is a deprecated-but-functional compat flag); switch when real-verified. `--json` left to `--adapter-args` so the default evidence path stays uniform text.
- 2026-09-09 (Stage 8b) — real `codex` binary absent here, so e2e runs against a POSIX shell stub via SKEIN_CODEX_BIN (same pattern/honesty as v0.1): proves spawn, argv, worktree, evidence, done - not codex's real CLI shape, hence verified:false. Stub e2e runs on POSIX CI and skips on Windows, where the same path was proven separately with a compiled stub exe.
- 2026-09-09 (Stage 8c) — opencode needs per-node `model` with no default: generic `config_flags` + `required_config` mechanism (missing key is an explicit error, never a silent default). opencode 1.18.30 binary present locally but holds zero provider credentials, so verified:false stands with a stronger reason than spec assumed.
- 2026-09-09 (Stage 8d) — README support matrix is generated from the registry between markers, with a test asserting byte-equality with `skein backends list`; prose cannot drift from `verified` state. Em-dashes broke cp1252 consoles again - source notes are ASCII-only.
- 2026-09-09 (Stage 8e) — aider added as pure profile data; no leak: claim.py, worktree.py, verify.py untouched (only graph.py gained inert node fields, supervisor gained backend resolution, CLI gained flags). "Universal" appears nowhere in docs/CLI output (absence enforced by test).
- 2026-09-09 (follow-up) — em-dash/cp1252 is a pattern (CLI icons, then profile source notes), so tests/test_ascii.py now fails the suite on any non-ASCII under src/skein. Boundary is deliberate: docs prose may stay UTF-8 (never printed by the tool); the README matrix is transitively covered by the byte-equality lockstep test.
- 2026-09-09 (follow-up) — git-log-scoping fix: confirmed the SAME fix from the real-backend pass, still intact, NOT a Stage 8 re-fix/regression (Stage 8 never touched git_commit_log). The gap was test coverage, now closed: test_log_commit_scoped_to_skein fails against unfixed code (verified by temporary revert) and passes with it.
- 2026-09-09 (follow-up) — explicit reminder: when a real codex binary becomes available, test `--sandbox workspace-write` before assuming `--full-auto` still works; upstream is actively moving off it (profile keeps spec-literal --full-auto until then).
- 2026-09-09 (completion pass) — web canvas is stdlib-only (ThreadingHTTPServer + dependency-free SVG UI, no React Flow build step); CLI and web share one edit ruleset (edits.py) so human_interrupt semantics cannot drift between surfaces.
- 2026-09-09 (completion pass) — blast inference compresses by parent directory (3+ files) and stays exact-path otherwise; suggestions are print-only, applying is always an explicit node edit.
- 2026-09-09 (completion pass) — sync auto-merges log conflicts by line union (safe because append-only + order-insensitive reduction) and rebuilds the derived graph; non-.skein conflicts abort untouched for manual resolve.
- 2026-09-09 (generality pass) — any CLI is addable as data: `skein backends add/remove` with JSON profiles in `.skein/backends/` (repo, team-shared) or `~/.config/skein/backends/` (user); repo wins on clash, broken files warn-and-skip, built-ins are unremovable. Router binaries count as backends too - the engine never inspects what the binary is.
- 2026-09-09 (generality pass) — providers/platforms plug in through CLIs, not around them: model choice stays a backend concern (backend_config / adapter-args). A pure HTTP endpoint with no agentic loop does not fit the adapter contract (the backend must act on files); documented as a boundary, not built.
- 2026-09-09 (generality pass) — dash-leading `--headless` values need `--opt=value` form (argparse eats bare `-p`); documented in help text rather than worked around.
- 2026-09-28 (Phase 1: correctness) — fenced claims: attempt_id + claim_token minted at claim time, immutable; every later mutation presents the live token. Stale attempts cannot complete/heartbeat/revive. Tokenless legacy lifecycle events are rejected, not grandfathered through the live path.
- 2026-09-28 (Phase 1) — human_interrupt clears ownership atomically and parks at needs_human; the supervisor no longer follows it with force-release (which dragged the node back to unclaimed and let the scheduler re-run human-stopped work).
- 2026-09-28 (Phase 1) — reaper releases carry reaped_as_of (decision time) separately from the event timestamp and are scoped to reaped_attempt_id: a delayed duplicate release can never wipe a newer claim. An earlier cut timestamped the release at the future decision time, which sorted it after a later real claim; the separate field fixes the ordering without losing the audit trail.
- 2026-09-28 (Phase 1) — no silent base substitution: base_branch_for raises BaseCommitUnavailable for unknown nodes, missing deps, or deps with neither result commit nor legacy branch. ensure_worktree resolves the base ref and refuses to create from a missing ref. Downstream nodes branch from dependency result commits; the result record (base/result/changed/diff/attempt) makes every done node a reusable, auditable base.
- 2026-09-28 (Phase 1) — integration is a first-class attempt: __integrate nodes are claimed by skein-auto-merge, merge in a temp worktree, verify, and checkpoint a result commit. They are exempt from recursively requiring their own __integrate node. The old auto-complete path (events appended without a holder) is gone.
- 2026-09-28 (Phase 1) — repo lock lives at .git/skein.lock (never stageable via .skein); heartbeat commits off by default; all Skein git writes use -c user.name/email flags so user config is never touched; skein init no longer overwrites existing repo identity.
- 2026-09-28 (Phase 1) — execution runtime: continuous stdout draining (read-after-exit deadlocked past the 64KB pipe buffer), 1MB output cap with truncation noted in evidence, process-group kill on abort/timeout (POSIX; best-effort terminate on Windows), DEVNULL stdin except stdin-mode adapters which get the prompt fed once. Verification commands run through the same bounded runner. Full canonical-runtime unification (adapter stdin modes + output parsers + supervisor interrupt loop as one path) remains Phase 2 work.
- 2026-09-28 (Phase 1) — snapshot metadata digests both log.ndjson and the generated graph.json: a corrupted graph.json is rebuilt from the log instead of being trusted because the log is unchanged. Wall clock remains the primary cross-machine order key (not a true Lamport/HLC); snapshot load re-hashes the whole log (fine at current scale, revisit with growth).
- 2026-09-28 (Phase 2: canonical execution runtime) — `runtime.execute()` is the single spawn/drain/kill path: supervisor, verifier, and `ProfileAdapter.run()` all go through it. Separate stdout/stderr capture preserves the backend's exact `(stdout, stderr, exit_code)` triple for its output parser; the supervisor applies the profile parser so evidence matches `adapter.run()`. Missing binary is exit 127 everywhere (the old supervisor `Popen` could raise `FileNotFoundError` out of `run_node`). Verification is cancellable via `should_abort`, wired to the supervisor's interrupt check. Windows tree kill is real via `taskkill /PID /T /F` (the old best-effort direct-child terminate orphaned grandchildren); the tree-kill tests embed the pidfile path with forward slashes after the `r'C:\...'` form proved to be a `SyntaxError` on Windows (`\U` unicode escape).
- 2026-09-28 (Phase 1/2: Windows pipe-drain wedge) — `os.set_blocking(fd, False)` does not reliably make Windows anonymous pipes non-blocking, and the failure is silent (`_make_nonblocking` swallowed the OSError). The drain loop then blocked in `os.read()` on the empty pipe for silent children, so the poll loop never reached the deadline check: the 120s tree-kill tests slept to completion (exit 0 at 120s) instead of dying at 2s, and the supervisor's adapter timeout never fired (outcome `done` instead of `failed`). The chatty tests passed throughout, which masked it: they only proved draining works when the child writes. Fix: on Windows each read is gated on `PeekNamedPipe` reporting waiting bytes (`_windows_pipe_has_data`); POSIX keeps non-blocking mode and `_make_nonblocking` is now POSIX-only. Regression test `test_run_bounded_silent_child_times_out` (silent 30s sleep, 2s timeout, must return 124 quickly) fails against the old code and passes with the fix.
- 2026-09-28 (Phase 3: worktree lifecycle) - `remove_worktree()` had no callers, so node deletion leaked worktrees. It is now called from `edit_node()`'s delete path, which the CLI (`skein node delete`, plus the legacy `node edit --delete`) and the web canvas share: one rule, no drift. The call happens after the `node_removed` event is appended, and `remove_worktree()` reads through `reduce_events` (not `load_graph`) because `load_graph` hides removed nodes; a first cut read `load_graph` and silently skipped removal, caught by the new delete tests.
- 2026-09-28 (Phase 3: base pinning) - the base for a branch-named base (e.g. `main`) cannot be re-resolved on reuse: every skein event commits `.skein`, so the branch moves under the worktree and a re-resolved comparison always "diverges". The worktree record pins the resolved `base_commit` SHA at creation and reuse treats the pinned SHA as authoritative: HEAD equal to it or descended from it is fine, anything else is refused. Only pinned-SHA bases (dependency result commits, immutable by nature) are re-resolved on reuse, to catch the dependency having re-run (done -> unclaimed -> claimed -> completed is a real operator flow).
- 2026-09-28 (Phase 3: result verification) - `verify_result_record()` checks object existence for both commits, ancestry of result under base, and equality of recorded vs recomputed numstat diff stats. The supervisor already records a real SHA as the result's `base_commit` (`rev-parse HEAD` at run start), so verification compares SHAs, never moving branch names.
- 2026-09-28 (Phase 3: gc safety) - `gc_worktrees()` never removes the main working tree (explicit path guard plus `git worktree remove`'s own refusal), never touches claimed/in-progress worktrees, and removes unregistered directories only under the skein-controlled `.skein/worktrees` root.
- 2026-09-28 (Phase 4: retry accounting) - `max_retries` counts retries AFTER the initial attempt, so `fail_node` retries while `failures_used < max_retries` (failures_used excludes the current failure). With max_retries=1 the first failure re-queues with backoff and the second parks at failed. 0 means the first failure parks immediately. The literal `<` in the spec only works with this "prior failures" definition, which is what is recorded as `attempts_used` on the failed event.
- 2026-09-28 (Phase 4: attempt history) - attempt entries are built in `reduce_events` from the live claim record plus the terminal event, never from a side channel; legacy tokenless claims (no attempt_id) record no entry because there is no stable attempt to attribute. History is capped at the last 20 entries per node to bound log-derived graph growth.
- 2026-09-28 (Phase 4: scheduler waits out backoff) - `run --all` sleeps until the earliest pending `retry_at` when no node is eligible but retries are still scheduled, in <=5s chunks so Ctrl-C stays responsive. Without the wait, a scheduler pass would silently drop every pending retry. A node whose dependency failed is reported under "not run" with the eligibility reason instead of being retried forever.
- 2026-09-28 (Phase 4: dead parameter) - the unused `claim_node(max_retries=...)` parameter was removed rather than wired: the retry policy belongs to the node record (set at add/edit time, visible in status and the web API), and no caller ever passed the argument.
- 2026-09-28 (Phase 5: divergence ignores control-plane churn) - every claim/complete appends a `.skein` commit, so a raw "target HEAD != recorded base" comparison would force `--force` on every ship. Divergence is defined as a non-empty `git diff --name-only base target -- . ':!.skein'`: real file movement warns, event-log churn does not. Verified by the shipping tests (a dependent whose base is the dep's result commit ships cleanly after the dep ships).
- 2026-09-28 (Phase 5: ship --all relaxes the divergence guard) - sequential ships in one run legitimately move the target for the next node, so `ship_all` passes force internally; merge conflicts still abort per node and surface as skips. The guarded interactive path is single-node `skein ship`.
- 2026-09-28 (Phase 5: one release verb) - `skein release <id>` already released claims, so the tag command could not take the same name cleanly. One `release` parser now disambiguates by target: a live node id releases its claim (unchanged behavior, still in the README), anything else is validated as a tag name. A tag colliding with a live node id always takes the claim path; documented here because it is a real semantic choice.
- 2026-09-28 (Phase 5: release event has no derived node state) - releases are repo-level, not node-level, so `apply_event` ignores the `release` type for reduction (anchored at the reserved `skein-release` id) and `shipping.list_releases()` scans the log instead. This keeps `graph.json` free of non-node records that every CLI view would have to filter.
- 2026-09-28 (Phase 5: integration conflicts park, not release) - the old path released the `__integrate` node back to unclaimed on conflict, which silently dropped the conflict context and let the scheduler treat it as ordinary pending work. It now appends `human_interrupt` (action edit, claim cleared atomically) plus a `node_edited` handoff note carrying the conflicted file list, so `skein status` shows exactly what needs resolving and the child stays blocked naming the parked node.
- 2026-09-28 (Phase 5: release guard is ancestry-aware) - the unshipped-done-nodes guard counts a node as shipped when its result commit is already an ancestor of the target, not only when a `shipped` event exists. The CLI itself tells the user to resolve conflicts manually and ship again, and the follow-up ship reports "already shipped"; blocking the release afterwards would punish the workflow the tool recommends.
